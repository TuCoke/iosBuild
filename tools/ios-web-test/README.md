# iOS 独立网页实验台

用于通过 FRP 查看 iOS 真实画面并测试点击、滑动和输入，不接入 Agent 或 WebRTC。

运行 `start.bat`，在 Chrome/Edge 打开 `http://127.0.0.1:18790/`。手机映射地址默认 `http://49.235.187.13:18990`，可在页面修改。需先安装包含 `/video/ws` 的新版 AgovHost；旧包不会因刷新网页获得该能力。

## 当前链路

```text
视频：iOS SDK → /video/ws → frpc → frps → 浏览器 WebCodecs
操作和状态：浏览器 → 本机 Python HTTP 代理 → FRP → 手机调试 API
```

Python 仍负责提供本地页面和转发原有 HTTP 操作，但不再接收、缓冲或转发视频。视频地址直接由映射地址生成，例如 `ws://49.235.187.13:18990/video/ws`。不要把映射改成手机本机的 18989 控制端口。

FRP 保持 `type = "tcp"`、`localIP = "127.0.0.1"`、`localPort = 18990`、`remotePort = 18990` 即可；无需增加视频端口，也不需要让 FRP 理解 H.264。正式 HTTPS 页面须使用 WSS 入口，当前本地 HTTP 页面可用于联调。

## 协议与生命周期

- WS 首条 JSON 为 `{type:"start", token:"调试口令", options:{durationSeconds:60,maxSize:720,fps:15,bitrate:800000}}`。口令不拼到 URL，鉴权前不申请编码器。
- 服务端先返回 `started`，再发送 AGV1 二进制帧。每条消息是 40 字节大端帧头加一个完整 Annex B 访问单元；序号、真实 PTS、宽高、负载长度、配置版本均显式传递。
- 帧头偏移：0 magic `AGV1`；4 flags（bit0=关键帧）；5..7 保留；8 序号 u64；16 PTS 微秒 u64；24 宽 u32；28 高 u32；32 负载长度 u32；36 配置版本 u32；40 起为 H.264。
- SPS/PPS 或尺寸变化时，在关键帧上更新配置版本；浏览器重置解码器。解码积压过大时等待新的关键帧，不无限播放旧画面。
- 视频关键帧和码率控制发送 `{type:"keyframe"}`、`{type:"bitrate",bitrate:800000}`，仅作用于本连接拥有的会话。
- 断开连接、正常限时结束或服务停止都会释放本连接的编码器。重复启动明确拒绝；不抢停其他用户正在测试的会话。时长仍为 1..120 秒的调试上限，不是正式云控长连接方案。
- 服务端每 5 秒 ping、15 秒 pong 超时，单次写入超时 3 秒；视频队列有界。网页连续 18 秒无视频帧会明确报错并断开，不把无限等待显示成“正常播放”。
- WS 只接受同源、本机实验台 `http://127.0.0.1:18790` / `http://localhost:18790` 或无 Origin 的已鉴权诊断客户端；其他 HTTP 接口不开放 CORS。更换网页部署来源时须显式增加可信来源。

## 验证边界

`node --test h264.test.mjs` 验证帧头、时间戳与 Annex B 分包；Go 调试接口测试使用替代视频源验证真实 WS 握手、鉴权、控制、到期和清理。这些不证明 iOS 编码已在真机生效。须用新安装包复验 FRP、WebCodecs 和前后台切换。

原有 `/video/stream` HTTP 下载接口保留，用于录制样本和对照排查。视频 WS 和 HTTP 下载共用同一 SDK 所有权，一次仅允许一个采集会话。
